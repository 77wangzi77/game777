# 关卡设计（细则）

> 对接：剧情关卡 VS、战斗系统、角色系统  
> 平台：PCVR · Unity  
> 状态：按你口述锁定胜负与结算流

---

## 1. 角色进入 · 出生区域

| 项 | 规则 |
|----|------|
| 入口 | 角色 **进入出生区域** 后，本关正式开始计时/接任务 |
| 出生点 | `SpawnVolume` / 出生锚点；面向关卡前进方向 |
| 初始化 | 读档或新开：刷 HP/MP/SP（或读档值）、清本关临时 flag、挂关卡规则组件 |
| 安全区 | 出生区域内默认无敌遇敌；出区域后按关卡刷怪/事件 |
| VR | 传送落点落在出生区地面；校准高度后给「关卡开始」弱提示 |

### 1.1 流程

```
加载关卡 → 放置角色于出生区域 → 播可选入场 → 激活关卡规则 → 开始限时(若有) → 可操作
```

---

## 2. 关卡规则 · 胜负判定

### 2.1 失败（游戏失败）

满足 **任一** 即判定 **失败**，进入结算：

| 条件 ID | 条件 | 说明 |
|---------|------|------|
| F_DEAD | 角色进入 **死亡状态** | HP≤0 且走完死亡流程（或即时判负，待填；默认死亡后判负） |
| F_QUEST | **未完成任务** 且关卡结束条件触发 | 如限时结束仍未完成必要任务 |
| F_QUIT | **玩家中途退出游戏** | 宣布失败，并进入结算界面 |
| F_OTHER | 关卡脚本失败点 | 可选（坠崖、关键 NPC 死等）待填 |

### 2.2 胜利

满足 **任一** 可走胜利结算（具体关卡可只开子集）：

| 条件 ID | 条件 | 说明 |
|---------|------|------|
| V_BOSS | 角色 **击杀成功 BOSS** | Boss 死亡事件派发 |
| V_TIME_QUEST | 在 **关卡限制时间内完成任务** | 限时 + 任务完成双满足 |
| V_QUEST | **完成关卡任务** 后触发结算 | 可不依赖击杀（剧情关） |

> 胜利后：**触发结算系统**。

### 2.3 判定优先级（建议）

1. 若已胜利 flag → 不转失败  
2. 退出（F_QUIT）→ 立即失败结算  
3. 死亡（F_DEAD）→ 失败结算（除非关卡允许石灯重试且重试次数&gt;0）  
4. 限时到 + 未完成 → F_QUEST 失败  
5. Boss 击杀 / 任务完成 → 胜利结算  

**石灯重生是否算「未失败」：** 若本关允许重生，则死亡不立刻 F_DEAD，扣次数；次数用尽再失败。默认：**可配** `allowRespawn` / `respawnCount`。

---

## 3. 限时

| 项 | 规则 |
|----|------|
| 字段 | `timeLimitSec`；`0` = 不限时 |
| 开始 | 离开出生区或「关卡开始」事件（待填；建议关卡开始就计） |
| UI | 倒计时只读显示 |
| 到期 | 未达胜利条件 → 失败；已达则可被胜利抢先 |

---

## 4. 中途退出

| 项 | 规则 |
|----|------|
| 触发 | 玩家主动退出本关/返回标题/强制杀进程前的正常退出菜单 |
| 判定 | **宣布游戏失败** |
| 下一步 | **进入结算界面**（失败样式） |
| 存档 | 不写胜利；可写「上次失败」统计；剧情进度是否回滚 → 待填（建议：未过关不推进章节 flag） |

---

## 5. 结算系统（触发后）

| 项 | 规则 |
|----|------|
| 入口 | 胜利或失败判定成立后调用 `SettlementSystem.Open(result)` |
| 结果 | `Win` / `Lose` |
| 展示 | 胜负标题、任务完成列表、击杀 Boss 与否、用时、基础奖励（失败可无奖或安慰奖） |
| 操作 | 返回出生/重试本关/回主界面（按钮可点；**小地图仍不可点**） |
| VR | 结算板放舒适距离；可坐姿确认 |

### 5.1 结算数据草案

```json
{
  "levelId": "LV_xxx",
  "result": "Win|Lose",
  "reason": "V_BOSS|V_QUEST|V_TIME_QUEST|F_DEAD|F_QUEST|F_QUIT",
  "timeUsedSec": 0,
  "timeLimitSec": 0,
  "bossKilled": false,
  "questsDone": [],
  "questsFailed": [],
  "rewards": []
}
```

## 6. 关卡配置结构（草案）

```json
{
  "levelId": "LV_inn_night",
  "displayName": "残简三声",
  "spawn": {
    "spawnPointId": "SP_birth",
    "safeZone": true
  },
  "timeLimitSec": 0,
  "allowRespawn": true,
  "respawnCount": 3,
  "win": {
    "modes": ["V_QUEST", "V_BOSS"],
    "requireAll": false
  },
  "lose": {
    "onPlayerDeath": true,
    "onQuit": true,
    "onTimeoutIncomplete": true
  },
  "questsRequired": ["QM5"],
  "bossId": "B_host",
  "settlementProfile": "default"
}
```

| 字段 | 说明 |
|------|------|
| spawn | 出生区域/点 |
| timeLimitSec | 0=不限时 |
| allowRespawn / respawnCount | 死亡是否立刻判负 |
| win.modes | 启用的胜利条件 |
| lose.onQuit | **true**：中途退出=失败并结算 |
| questsRequired | 完成哪些算 V_QUEST |
| bossId | V_BOSS 监听对象 |

---

## 7. 状态机（关卡）

```
Load → InSpawn → Playing → (WinCheck|LoseCheck) → Settlement → ExitOrRetry
```

- `Playing` 中：监听死亡、Boss 击杀、任务完成、限时、退出  
- 进入 `Settlement` 后暂停玩法输入（保留 UI 确认）  

---

## 8. 验收

1. 从出生区域开局，逻辑正确初始化  
2. 击杀 Boss 或完成关卡任务 → 胜利结算  
3. 限时内完成任务 → 胜利；超时未完成 → 失败结算  
4. 角色死亡且无重生次数 → 失败结算  
5. 中途退出 → **失败** 并出结算界面  
6. 结算数据 reason 正确  

---

## 9. 待填
